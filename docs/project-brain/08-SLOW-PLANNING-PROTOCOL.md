# Slow Planning Protocol

Status: `ACTIVE`

## Meaning of “slow”
IRIS planning proceeds one module at a time. For the active module, all five sessions are explored deeply before moving to the next module.

## Technology capture
Every session must search for and evaluate:
1. existing technologies that can improve quality, performance, reliability or production;
2. reusable technology already proven in UGAS/HIVE/CORE;
3. proprietary candidate technologies worth designing for IRIS.

Every technology entry must contain:
- stable ID and name;
- existing/proprietary-candidate classification;
- concise purpose;
- operating model;
- expected benefit;
- dependencies;
- risks/failure modes;
- benchmark/proof plan;
- status: PROPOSED / ACCEPTED / REJECTED / SUPERSEDED / IMPLEMENTED / VALIDATED;
- destination module(s).

## Novelty rule
“Proprietary candidate” means an IRIS-owned design candidate. It is not a claim of patentability or global novelty. Prior-art research is required before any novelty claim.

## Persistence
Chat discussion is not the source of truth. Accepted technology and decisions are committed to the IRIS repository and linked to the active module/session.

## Implementation gate
Technology planning does not authorize implementation. Implementation requires the normal Work Order, dependency, acceptance and evidence gates.
